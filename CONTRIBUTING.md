# Contributing

See [README.md](README.md) for setup and [PROJECT.md](PROJECT.md) for team responsibilities.

1. Create a branch named `<github-alias>/<short-name>`, for example `frsanchez/github_action`.
2. Keep each change focused and submit every change through a pull request.
3. Before requesting review, run `python -m tox` and ensure all automated tests, lint, and formatting checks pass, including GitHub Actions checks on the PR. Apply formatting with `python -m tox -e format` if needed.
4. Describe what changed, why, and how you validated it. Link any related issue and request a teammate’s review.

Architecture and evaluation decisions require team agreement. Their documents remain placeholders until the team agrees on the approach.
